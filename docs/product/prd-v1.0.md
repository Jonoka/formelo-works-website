## 01 项目定义与成功标准

### 1.1 产品定位

为中国服装工厂建设英文 B2B 官网，面向海外初创及成长型服装品牌，展示工厂的小批量定制能力、核心品类、样品与生产流程，以 SEO 为主要入口，引导潜在客户通过工厂邮箱或 WhatsApp 直接沟通。

网站以工厂自身品牌和身份对外呈现，可使用 “Our Factory”“Work directly with our factory”等真实表述。你们是网站建设与运营方，不是网站对外叙事中的中间商；工厂承担询盘接待、沟通、报价、打样、生产、交付和售后。

**产品边界：网站帮助客户找到工厂、判断是否匹配并开始联系，不在站内接收项目、形成订单或管理客户文件。**

### 1.2 目标与非目标

| 类别 | 定义 | 如何判断 |
|---|---|---|
| 获客目标 | 吸引需要工厂实际优势品类及小批量服务的海外买家 | 搜索查询与落地页相关性；工厂反馈的真实、可承接询盘 |
| 转化目标 | 让客户方便地开始邮件或 WhatsApp 联系 | 联系入口可见、链接正确、真实发信 / 发消息测试通过 |
| 信任目标 | 解释实际工厂能力和小 MOQ 的适用条件 | 工厂审核资料；用户能找到 MOQ、打样、品类、工厂身份 |
| 运营目标 | 运营人员不改代码即可维护主要内容 | CMS 修改页面、品类、文章与联系方式后可发布 |
| 迭代目标 | 在不重建全站的情况下增加品类和文章 | 使用现有内容模型与模板增加内容即可生成新页面 |
| 非目标 | 首期覆盖所有品类、采购流程和贸易管理 | 不用“大而全”目录、在线商城或客户门户作为交付条件 |

网站交付验收关注功能、内容、可访问性和部署质量。排名、收录时间、自然流量、询盘和订单结果属于上线后运营评估，不能作为框架或页数带来的保证。[S06][S07]

### 1.3 业务结果的计量边界

联系点击、实际消息、合格询盘、打样和订单是不同层级。网站只能记录允许采集的页面与点击行为；工厂才能确认实际收到消息及业务结果。

建议主要经营指标为“工厂确认来自本站的新增合格询盘数”。合格定义为：客户确有商业项目、联系方式可沟通，品类及数量条件初步可承接。没有公司网站或 Tech Pack 不自动判为不合格。网站来源不明确时记录“未知”；同一项目跨邮箱、WhatsApp 沟通时由工厂去重。

### 1.4 职责与批准权

| 工作 | 网站团队 | 工厂 |
|---|---|---|
| 范围、页面、交互、代码、部署 | 主责；维护 PRD 与验收记录 | 确认品牌及业务要求 |
| 关键词研究、英文内容、SEO | 主责；整理专业内容 | 提供资料并核对业务事实 |
| MOQ、打样、交期、工艺与资质 | 统一展示，不自行承诺 | 提供并最终确认 |
| 联系方式配置与测试 | 配置、跨端测试、变更同步 | 提供可用账号与接待人，实际收发测试 |
| 报价、付款、订单与履约 | 不在本站范围内 | 全权负责 |
| 运营复盘 | 分析搜索与页面行为 | 提供去标识的询盘结果汇总 |
| 账号与资产 | 管理受授权的开发、内容权限 | 与网站负责人确认归属及恢复权限 |

网站负责人可以兼任开发和运营，工厂资料审核人可以兼任接待人；不要求新增岗位或软件。开始开发前填入实际负责人，上线前完成业务内容确认和渠道收发确认。

## 02 用户角色、场景与用户路径

### 2.1 主要用户

| 用户 | 当前状态 | 最需要知道的内容 | 预期动作 |
|---|---|---|---|
| 初创品牌创始人 | 有创意或参考图，可能不懂生产术语 | 能否小单、如何开始、需要什么资料 | 阅读流程后直接联系 |
| 已有设计的采购者 | 有款式、数量或 Tech Pack | 品类能力、面料工艺、MOQ、打样条件 | 从品类或样品联系 |
| 寻找替代工厂的品牌 | 已有产品，希望换供应商或补单 | 工厂真实性、相关样品、质量与稳定性 | 查看工厂后发起沟通 |
| 网站运营人员 | 维护英文内容并分析效果 | 易编辑、易发布、可回滚 | 更新页面与文章 |
| 工厂业务接待人 | 在邮箱 / WhatsApp 处理客户 | 来自哪个品类、是否有样品参考 | 沟通并回传必要结果 |

不面向零售下单用户设计购物车，也不把设计资料完整程度设为访问或联系门槛。

### 2.2 关键用户故事

| 编号 | 用户故事 | 对应能力 |
|---|---|---|
| US-01 | 我搜索某类服装工厂后，希望直接判断能否做我的产品 | 品类模板、真实样品、能力与 MOQ 说明 |
| US-02 | 我是首次做品牌，希望不用懂所有术语也能开始 | 合并制造服务页、资料清单文章、可直接联系 |
| US-03 | 我看到一个样品，希望不重新描述也能咨询 | 样品编号和联系上下文 |
| US-04 | 我的设备没有可用邮件程序，希望仍能拿到地址 | 可见邮箱、复制和手动选择 |
| US-05 | 我想确认不是中间平台，希望查看工厂本身 | Our Factory、厂址、真实生产照片 |
| US-06 | 我修改联系方式，希望全站一致更新 | 单一全局配置、构建发布与全站验证 |
| US-07 | 我不修改代码，希望持续发布采购文章 | Sanity 文章模型、模板和发布流程 |

### 2.3 主路径与系统边界

```text
路径 A：搜索 → 品类页 → 样品 / 制造条件 → Email 或 WhatsApp → 客户主动发送
路径 B：搜索 → 采购文章 → Manufacturing 或品类页 → 直接联系
路径 C：首页 → Our Factory → Contact → 邮箱 / WhatsApp
路径 D：Sanity 编辑 → 事实审核 → 发布 → 构建 → 正式站验证

网站可控制：内容、跳转链接、复制操作、允许采集的点击事件。
网站不可确认：客户端是否打开成功、客户是否点击发送、工厂是否已读、是否成交。
```

不设置“已提交成功”页面，不用跳转后的计时器模拟“工厂已收到”。文章与品类页都可直接联系，不强制先经过 Contact。

## 03 首期范围与信息架构

### 3.1 优先级定义

P0 为首期交付必须完成的能力；P1 为上线后有证据再开发的能力；P2 为长期候选。P0 中的统计接口需要实现与验证，但第三方分析默认关闭，是否启用另按第 12 章确认；关闭状态属于允许的正式运行模式。

| 范围 | 首期决策 |
|---|---|
| 对外内容 | 英文；工厂官网身份；两个优势品类；两篇文章 |
| 联系方式 | 工厂邮箱 + WhatsApp；均可从核心页面直接访问 |
| 内容管理 | 四类内容模型；固定模块，不做任意拖拽建站 |
| SEO | 静态 HTML、元数据、规范 URL、sitemap、结构化数据、Search Console |
| 工程 | 域名、HTTPS、真实 404、移动端、构建校验、备份与回滚 |
| 不在本期 | 表单、上传、询盘保存、CRM、业务聊天集成、支付、自动报价、多语言、站内搜索 |

### 3.2 页面清单与索引策略

以下两个品类名称是路径示例，选定真实品类后在首次上线前替换。文章主题为本次建议基线，可调整标题，但应保留两种采购问题分工。

| 页面编号 | 页面 / 路由 | 模板 | 索引 |
|---|---|---|---|
| PG-01 | 首页 `/` | Home | 是 |
| PG-02 | 制造服务 `/manufacturing/` | Manufacturing | 是 |
| PG-03 | 品类 A `/clothing/t-shirts/` | Category | 是 |
| PG-04 | 品类 B `/clothing/hoodies/` | Category | 是 |
| PG-05 | 工厂 `/our-factory/` | Factory | 是 |
| PG-06 | 博客 `/blog/` | BlogIndex | 是 |
| PG-07 | 联系 `/contact/` | Contact | 是 |
| PG-08 | 隐私 `/privacy/` | Legal | 否，noindex |
| PG-09 | 询价资料 `/blog/what-to-send-for-a-clothing-quote/` | Article | 是 |
| PG-10 | MOQ 解释 `/blog/moq-per-style-per-color/` | Article | 是 |

**总计 10 个内容 URL、8 类页面模板；默认 9 个可索引 URL。** 隐私页可从页脚访问，但不进入 sitemap，这是本项目的索引选择，不是法律要求。404、robots.txt 和 sitemap 不计入内容页数量。额外政策页面只有在实际工具或适用要求确定后才纳入变更范围，不因数量目标省略必要披露。

### 3.3 导航与路由约定

NAV-01：顶部为 Logo、Clothing、Manufacturing、Our Factory、Blog、Contact Us。Logo 链接首页；Clothing 是展开控件，内含两个已发布品类，不链接到不存在的 `/clothing/`。

NAV-02：页脚包括主要页面、Privacy、可见邮箱、WhatsApp 和工厂品牌。没有真实社交账号时隐藏整组社交链接，不显示空图标或 `#` 假链接。

NAV-03：品类面包屑为 Home → 当前品类；文章为 Home → Blog → 当前文章；其他内页为 Home → 当前页面。当前项不是无意义链接；首期不得生成虚构的 Clothing 父级地址。

所有站内路径统一小写英文短横线，内容路径以 `/` 结尾。slug 一旦上线保持稳定；变更通过重定向清单处理。保留不存在路径的真实 404，不把所有未知路径返回首页。

### 3.4 先合并的内容及未来拆分

MOQ、定制方式、打样与生产步骤在 Manufacturing 分区呈现；质检在 Our Factory 呈现；面料、工艺与样品在品类页呈现；FAQ 分布在相关页面。首期不为近义词、颜色、尺码、作者、标签或国家创建独立入口页。

新增专题需满足“真实能力和资料、独立采购问题、清楚的维护人”三个条件，并有搜索或询盘依据。拆页后原页面保留摘要和链接，不直接复制整段正文。

## 04 全站公共体验与组件

### 4.1 布局基线

UI-01：采用响应式布局，不做单独移动站。建议断点：小于 768px 为手机、768–1023px 为平板、1024px 及以上为桌面；导航在小于 1024px 时折叠。正文最大宽度约 1200px，文章阅读区约 760px。数值为设计基线，视觉评审可微调，但需通过测试矩阵。

UI-02：移动端正文不小于 16px，主要触控按钮不小于 44×44 CSS px，长邮箱和英文标题允许自然换行。正常浏览不出现整页横向滚动；参数表在手机上优先改为逐项说明。

### 4.2 公共组件规格

| 编号 / 组件 | 行为与规则 | 状态及验收 |
|---|---|---|
| NAV-04 Header | 桌面下拉可点击 / 键盘展开，不仅依赖 hover；手机为非模态折叠菜单 | 展开状态可感知；Esc 关闭；焦点回到触发点；无 JS 仍可访问核心链接 |
| UI-03 Breadcrumb | 使用真实可访问层级，与结构化数据一致 | 不链接不存在页面，不包含敏感查询参数 |
| UI-04 ContactActions | WhatsApp + Email 双入口，全站同一组件 | 使用真实 href；统计失败不拦截导航；上下文来源统一 |
| UI-05 MobileContactBar | 手机底部固定双按钮，桌面隐藏；除 Privacy / 404 外显示 | 内容预留底部高度及安全区；不遮挡页脚、菜单或隐私控件 |
| UI-06 FAQ | 使用原生 details / summary 或等价可访问实现 | 答案已在 HTML 中；无 JS 可展开；不从点击后 API 加载 |
| UI-07 SampleCard | 图片、公开编号、简要能力说明、双联系入口 | 不存在价格、库存、购物车、颜色 SKU 或详情空链接 |
| UI-08 ArticleCard | 标题、摘要、封面、发布日期 | 标题可点击；未发布文章不出现；图片失效不破坏布局 |
| UI-09 Image | 明确尺寸或比例、响应式图片、替代文本 | 非首屏懒加载；首屏关键图不默认懒加载；不拉伸变形 |

手机菜单采用页面内折叠而非全屏模态，减少焦点管理复杂度。菜单展开时临时隐藏底部联系条；无 JS 可用原生展开组件完成基础导航。所有原生链接均支持键盘 Enter 激活；复制使用 button。可访问性参照 W3C 指引落实键盘、焦点、对比度及重排测试，不把工具分数当作完整认证。[S16]

### 4.3 内容与视觉规则

视觉优先服务“制造能力与可信度”：真实车间、实物与细节摄影，清楚的参数和流程，统一按钮。首期不做轮播首屏、自动播放视频、扫码后才能联系或强制弹窗。资料不足时省略可选模块，不使用虚构工厂、品牌背书、证书或 AI 生成车间冒充实拍。

商业数字必须附计量方式和条件。MOQ、费用、时间不是视觉占位数字；不得默认出现“50 pcs”“24/7”“7 days”等未经工厂确认的信息。

## 05 核心商业页面需求

### 5.1 PG-01 首页

**目标：** 海外买家迅速了解工厂为谁生产、优势品类是什么，并能够查看能力或直接联系。入口包括品牌搜索、其他站内页面和外部链接；下一步为品类、制造服务、工厂或双渠道联系。

| 模块 / 编号 | 必要内容 | 交互与内容要求 |
|---|---|---|
| HOM-01 首屏 | 工厂定位 H1、简短说明、真实主图、双联系按钮 | 无需滚到页底即可找到联系；不把首页写成商城促销页 |
| HOM-02 核心品类 | 两个品类入口，各有图、名称及差异化摘要 | 卡片指向对应已发布品类；不出现 Coming soon 占位分类 |
| HOM-03 能力与证据 | 2–4 项经确认的优势，配证据性短说明 | 优势不必全部数字化；无法证明的承诺不展示 |
| HOM-04 制造摘要 | 定制、MOQ、打样摘要与制造页链接 | 数字来自共享业务规则；只做概览，不复制整页 |
| HOM-05 工厂与流程 | 工厂图片、简要介绍、3–5 步合作概览 | 进入 Our Factory 或 Manufacturing 对应区块 |
| HOM-06 常见问题与底部 CTA | 3 个左右采购问答与双联系入口 | 答案由工厂确认；无需填表即可联系 |

**首屏示例文案（待工厂审核）：**

> Custom Clothing Manufacturing for Emerging Brands
>
> Work directly with our factory in China to develop and produce your next collection.
>
> Chat on WhatsApp / Email Our Factory

模块顺序为推荐基线，可调整图片左右位置，但不得隐藏品类、工厂身份或联系入口。最低素材为一张真实首屏图、两类独立品类图、可公开工厂图及确认后的优势说明。

**页面验收：** H1 只有一个；两个品类可达；首页不展示示例业务数值；两个联系入口均带 `WEB-HOME` 上下文；所有模块可在无 JS 条件下读取。

### 5.2 PG-02 Manufacturing

**目标：** 在一个页面回答“如何定制、起订怎么算、准备什么、怎么打样”，而不是为每个服务词分别开发一页。

| 模块 / 编号 | 必要内容 | 规则 |
|---|---|---|
| MFG-01 服务方式 | 工厂实际提供的方式及适用项目 | 能加标、能改版、能从零开发分别说明；未提供则不显示 |
| MFG-02 MOQ | 数量、计量单位、按款 / 色方式、混码、面辅料条件 | 精确数值未确认时使用真实条件说明；不拿示例数值发布 |
| MFG-03 资料准备 | 品类、预计数量、交付国家；设计 / 参考图为有则提供 | 不要求 Tech Pack 或企业邮箱才能开始联系 |
| MFG-04 打样 | 输入资料、确认点、修改方式、费用与时间说明 | 不承诺免费打样或无限修改；必要条件写在数字旁 |
| MFG-05 生产步骤 | 需求确认、样品、确认后生产、检查与交付 | 仅展示工厂实际流程；不开发进度跟踪功能 |
| MFG-06 FAQ 与 CTA | 高频问题、双联系入口 | 内容和品类差异相符；上下文为 WEB-MANUFACTURING |

固定区块锚点建议为 `#options`、`#moq`、`#prepare`、`#sampling`、`#production`、`#faq`。文章可链接到对应锚点；锚点不生成独立 SEO 页面。固定头部存在时设置滚动偏移，避免标题被遮挡。

MOQ 展示示例仅说明字段结构：“Minimum quantity: [confirmed value] per style / per color; size mixing: [conditions]”。没有统一 MOQ 时可以明确“因品类、面料和颜色而异，请查看对应品类并联系确认”，前提是工厂认可；不能从多个品类里取最小值当全站无条件承诺。

**页面验收：** 买家能找到 MOQ 单位与打样步骤；每个可展示服务都经工厂确认；首页、制造页、品类不存在冲突的全局数字；区块链接与双联系入口正常。

### 5.3 PG-03 / PG-04 品类页

**目标：** 承接“寻找该品类制造商”的采购意图，通过有差异的真实内容支持联系。两页共用模板，不共用一份仅换品类名的正文。

| 模块 / 编号 | 必要内容 | 规则 |
|---|---|---|
| CAT-01 标题与摘要 | 品类 + Manufacturing 服务定位、适合客户 | 标题示例：Custom Hoodie Manufacturing for Emerging Brands |
| CAT-02 样品区 | 建议 3–6 组真实样品；每组至少 1 张图、公开编号和简述 | 本期最低为每品类 3 组获准公开样品；不足需明确调整范围 |
| CAT-03 能力规格 | 面料、克重、版型、尺寸及工艺等适用信息 | 不适用字段隐藏；克重示例需注明对应样品或范围 |
| CAT-04 定制与 MOQ | 实际可改位置、数量算法、限制、打样摘要 | 业务规则有默认 / 覆盖逻辑；不能空写“Low MOQ” |
| CAT-05 品类证据 | 生产、检查或开发细节图及说明 | 可复用真实相关工厂资料，不编造客户项目 |
| CAT-06 FAQ 与关联内容 | 3–5 个采购问题，最多 2 篇相关已发布文章 | 暂无相关文章时隐藏该模块，不渲染空容器 |
| CAT-07 联系 | 页首、样品卡、页末双渠道入口 | 普通 CTA 带品类；样品 CTA 额外带公开 sampleCode |

**样品卡字段：** `sampleCode`、`name`、`summary`、`images` 为必填；`fabric`、`weightGsm`、`fit`、`techniqueNotes` 为有资料才填。公开编号建议如 `HD-001`，不得使用客户内部订单号。明确文字 “Examples of what we can make. Details are confirmed for each project.”，仅在其符合工厂实际时使用。

不在本期实现图片放大灯箱、样品独立详情、收藏、筛选、批量询价清单和下载资料。每张样品图有可阅读的说明；图片不承担唯一信息传达。

**空数据与异常：** 已发布品类缺关键图片、标题或 MOQ 说明时构建失败并指出具体字段；可选参数缺失则不显示。无效 slug 返回 404。工厂撤销某品类时先处理首页、导航、文章引用，再按第 10 章下线。

**页面验收：** 两类样品和能力确有差异；全部样品编码唯一；品类和样品上下文准确；不生成颜色 / 尺码 URL；与 Manufacturing 的总规则不矛盾。

### 5.4 PG-05 Our Factory

**目标：** 让买家确认实际生产主体、所在地、制造能力和质量控制方式。工厂真实自有身份是叙事前提，不写成撮合平台。

| 模块 / 编号 | 必要内容 | 规则 |
|---|---|---|
| FAC-01 工厂概况 | 工厂英文名称、所在地、实际业务和优势品类 | 厂龄、面积、人数和产能仅在确认后展示，不设必填数字 |
| FAC-02 真实照片 | 建议 4–8 张：车间、设备、团队、生产细节等 | 本期最低 3 张可公开工厂照片；每张说明实际工序 |
| FAC-03 生产能力 | 可完成的工序及开发支持 | 有外协的工序按实际描述，不扩写成“全部厂内完成” |
| FAC-04 质量控制 | 至少说明检查阶段、检查内容与异常沟通方式 | 不强制独立质量页，不声称零缺陷 |
| FAC-05 资质 / 案例 | 可选；真实证书、授权案例或自研样品 | 无资料整段隐藏；证书需核对主体、范围与有效期 |
| FAC-06 联系入口 | Email 与 WhatsApp；可链接至核心品类 | 上下文为 WEB-FACTORY |

不嵌入第三方交互地图，首期使用文字厂址或地区说明；对外地址由工厂确认。没有工厂视频不会阻止上线。页面验收须包含工厂审核记录，不以“图片看起来像工厂”作为通过依据。

## 06 博客与文章需求

### 6.1 PG-06 博客列表

BLG-01：标题可用 “Clothing Manufacturing Resources”，导航仍为 Blog。只展示已发布文章，按 `publishedAt` 倒序，同一时间按稳定 ID 排序。卡片显示封面、标题、摘要、日期；不显示虚构阅读量、点赞数或评论数。

BLG-02：首期单页展示全部已发布文章，无分类筛选、搜索、标签页或作者页。初始必须有两篇。后续达到约 12 篇时评估分页需求，但不能在未实现分页时硬截断列表导致旧文失去入口；分页属于 P1。

BLG-03：零文章状态提供简短说明和 Manufacturing 链接，仅用于异常降级；首期正式验收若不足两篇则不通过。卡片内不嵌套链接，所有文章标题直接链接详情。

### 6.2 PG-09 / PG-10 文章模板

ART-01：包括单一 H1、摘要、工厂团队或真实作者署名、发布时间、实质更新时间（有则显示）、正文、相关页面和双联系入口。主正文使用 H2 / H3 分层，正文编辑器不允许再插入 H1。

ART-02：支持段落、标题、列表、链接、图片、图注、简单表格和提示框；不允许任意脚本、iframe 或未经控制的 HTML。H2 达到 3 个时自动生成页内目录，锚点由稳定规则去重；内容均在 HTML 中。

ART-03：关联 1–2 个品类或 Manufacturing 页面，链接必须解析到已发布对象；文章末尾最多推荐 2 篇相关已发布文章，不推荐自身。初期文章不足时少显示，不补空卡片。

ART-04：不启用评论、强制登录、订阅弹窗和下载换邮箱。公开知识完整可读，联系入口自然出现。来源引用与工厂实际经验分开，不把通用行业经验写成该厂已具备的能力。Google 强调有帮助的原创内容，本项目不以固定字数或更新频率验收 SEO 价值。[S07]

### 6.3 两篇首发文章的内容任务书

| 内容项 | 文章 A：询价前资料 | 文章 B：MOQ 解释 |
|---|---|---|
| 建议英文标题 | What to Send Before Requesting a Custom Clothing Quote | Clothing MOQ Explained: Per Style, Per Color and Mixed Sizes |
| 解决问题 | 不懂外贸的品牌如何开始沟通 | 理解起订量的数量单位与影响因素 |
| 必讲内容 | 品类、款数、数量拆分、交付国家；有设计则提供；没有 Tech Pack 也可沟通 | 每款 / 每色 / 混码差异；面料与辅料条件；示范算例与适用边界 |
| 原创输入 | 工厂实际询价所需资料、可公开的空白资料清单 | 工厂真实规则、经审核的匿名算例 |
| 不得写 | 没有资料不能联系、保证立即精确报价 | 把示范数量写成工厂统一 MOQ |
| 内链 | Manufacturing 的 #prepare、相关品类 | Manufacturing 的 #moq、相关品类 |
| 联系上下文 | WEB-QUOTE-GUIDE | WEB-MOQ-GUIDE |

每篇以覆盖真实问题为验收，不设必须凑满的字数。发布前由运营检查英文、结构与内链，工厂检查事实与可公开范围。

## 07 联系页、隐私页与 404

### 7.1 PG-07 Contact

CNT-01：首屏显示 “Contact Our Factory”，提供可见邮箱、Email 按钮、Copy Email 按钮、WhatsApp 按钮及可见的国际格式号码。联系方式在至少桌面和手机各一台真实设备上完成主动收发测试；正确打开入口不等于工厂已收到消息。

CNT-02：显示接待部门或联系人、工厂确认的工作时段与明确时区、对外地址或地区说明。中国工厂时区可按工厂确认使用 UTC+8，不读取访客时区冒充工厂工作时间；不显示未经保证的在线状态或回复倒计时。

CNT-03：提示客户可提供品类、预计数量、交付国家及已有设计 / 参考图。该提示不是表单，没有必填输入框、上传控件、同意勾选或提交按钮。可用文案：“Not sure what to prepare? Tell us what you would like to make.”

CNT-04：说明邮件按钮会打开邮件程序，无法打开时可复制地址；WhatsApp 可在可用客户端或 Web 流程继续。客户文件通过工厂沟通渠道处理，不进入网站 CMS。页面不展示“已接单”“已报价”等状态。

### 7.2 PG-08 Privacy

PRV-01：展示生效日期、工厂 / 网站的数据联系主体、托管与日志处理、实际启用的分析方式、联系跳转至第三方的说明、工厂通过邮箱 / WhatsApp 处理询盘的说明，以及权利请求联系渠道。具体文本须与实际服务商和适用要求一致，本文不替代针对目标市场的隐私法律意见。

PRV-02：即使没有表单，也不能宣称“绝不处理任何数据”。如有访问日志、分析或客户主动联系，须按实际情形说明。分析默认关闭；没有新增非必要追踪时，不为了外观增加一个无实际用途的 Cookie 弹窗。若启用需要同意管理的技术，须完成相应机制及政策审核后才加载。

PRV-03：页面为 200，可从页脚访问；默认 `noindex,follow`，不列入 sitemap；不加手机底部营销联系条。正文正常显示，不能用 robots.txt 阻断后期待搜索引擎读取 noindex。[S10]

### 7.3 工程页面 404

ERR-01：所有不存在路径返回 HTTP 404，而非 200 或统一跳首页。页面有英文错误说明、回首页、Manufacturing 和 Contact 链接，不出现表单或自动发送提示。

ERR-02：无效品类、文章 slug 和已下线且无替代的路径均执行相同规则。404 不进入 sitemap，不输出 Article / Product 等业务标记。站点发布配置须关闭“任意未知路径返回首页”的单页应用回退。

## 08 邮箱与 WhatsApp 联系功能

### 8.1 通用要求与上下文

CONTACT-01：所有联系链接由共享函数生成，号码、邮箱只从 `siteSettings` 读取；固定按钮文案和参数规则在公共组件维护，运营不能粘贴任意未审核的联系方式覆盖它。

CONTACT-02：普通按钮传入页面上下文；样品按钮增加公开样品编号。传入字段仅可来自受控内容模型：`pageKey`、`pageType`、`categoryCode`、`sampleCode`、`referenceCode`。没有品类时使用页面通用上下文，不误填首页或第一品类。

| 页面 / 场景 | referenceCode 示例 | 消息包含 |
|---|---|---|
| 首页 | WEB-HOME | 工厂网站、定制项目 |
| Manufacturing | WEB-MANUFACTURING | 制造服务与定制需求 |
| Our Factory | WEB-FACTORY | 工厂能力咨询 |
| Contact | WEB-CONTACT | 通用项目咨询 |
| 品类页 | WEB-HOODIES / WEB-TSHIRTS | 对应品类 |
| 样品卡 | WEB-HOODIES + HD-001 | 对应品类及公开样品编号 |
| 文章 / 博客 | WEB-QUOTE-GUIDE / WEB-MOQ-GUIDE / WEB-BLOG | 来源主题，不强行推断客户品类 |

referenceCode 用于帮助工厂识别页面来源，不是客户 ID，也不是 SEO 渠道证明；直接访问和其他渠道访问同一页面也会带同一代码。代码发布后保持稳定，即使标题修改也不自动改变。

### 8.2 WhatsApp 直达

WA-01：使用官方 Click to Chat 格式，不开发 WhatsApp Business API、消息同步或自动发送。号码保存为工厂确认的完整国际号码；链接使用仅数字格式，不带 `+`、空格、括号或分隔符，不擅自删除号码内部的零。[S01]

```text
https://wa.me/{international_digits}?text={encoded_message}
```

WA-02：预填内容控制在约 300 个英文字符以内（本项目约定，不是平台限制）。先按模板生成纯文本，再完整 URL 编码；只编码参数值，不重复编码整个 URL。包括 `&`、`+`、问号、换行和非 ASCII 字符的测试必须通过。

WA-03：使用真实 `<a href>`，默认当前浏览上下文导航，让浏览器 / 系统处理客户端或 Web 路径；不依赖 `window.open`、定时跳转、第三方脚本加载或 `onclick` 才生成链接。用户可自行新标签打开，不强制应用安装判断。

WA-04：工厂号码未确认、格式不合法或频道禁用时，不渲染损坏链接。正常上线要求两个渠道均可用；紧急运营降级可临时隐藏一个渠道并突出另一个，需记录原因和恢复动作，不视为初始双渠道验收通过。

WA-05：点击仅意味着尝试联系。官方预填内容仍需用户主动发送；不触发“询盘提交成功”事件、不展示感谢提交页、不宣称工厂已读。[S01]

**品类与样品消息示例：**

```text
Hi, I found your hoodie manufacturing page on your website.
I'd like to discuss a custom order for my brand.
Reference: WEB-HOODIES
Sample: HD-001
```

普通品类 CTA 不含 `Sample` 行；文章 CTA 使用文章来源，不自动附带无关样品。客户可以在 WhatsApp 内修改或删除预填内容。

### 8.3 Email 链接

EMAIL-01：可见地址和 `mailto:` 的收件人来自同一配置。单一工厂邮箱，不预填抄送 / 密送。地址须去除首尾空格并拒绝换行、多个收件人或附加 header 注入；不通过粗糙的正则禁止正常企业邮箱。

EMAIL-02：主题与正文分别编码，换行使用合适的编码方式。主题示例为 `[Website][Hoodies] Custom clothing inquiry`。正文建议简短，只带公开上下文和非强制资料提示，不含访问者身份、查询参数或自动追踪 ID。

```text
mailto:{factory_email}?subject={encoded_subject}&body={encoded_body}
```

EMAIL-03：`mailto:` 由用户邮件程序处理，不是网站发信 API；客户仍需自行发送，网站不能判断是否发送成功，也不能自动附加本地设计稿。[S02] 不配置 Resend 等事务邮件服务，不把企业收件邮箱与网站代发服务混为一项需求。

EMAIL-04：任何存在 Email CTA 的商业页，在同页可找到可见邮箱与复制入口（统一页脚即可；Contact 页首屏重复展示）。无 JS、没有默认邮件程序或外部程序未打开时，客户仍能手动选中地址。

### 8.4 复制邮箱

COPY-01：仅在用户主动点击时调用 Clipboard API，复制干净邮箱地址，不复制 `mailto:`、主题或正文。操作成功后在局部显示 `Email copied`，通过 `aria-live="polite"` 提供反馈，约 3 秒后恢复 `Copy email`。[S03]

COPY-02：权限拒绝、不支持 API、非安全环境或其他异常时显示 `Please select and copy the email address below.`，不展示虚假的成功反馈；可见文本始终能手动选择。禁用 JS 时隐藏依赖 JS 的复制按钮，保留地址。

COPY-03：重复快速点击不造成多次绑定或堆叠提示；统计仅在真正写入成功后记录复制成功，失败只在本地排错，不把错误对象、邮箱和堆栈发送给分析服务。

### 8.5 状态与降级矩阵

| 情况 | 用户体验 | 网站不得做 |
|---|---|---|
| WhatsApp 未安装或未登录 | 交给官方可用流程；同页保留 Email | 用计时器认定打开成功或失败 |
| 邮件程序未配置 | 用户可复制或手动选择地址 | 宣称邮件已发送 |
| 分析服务被屏蔽 | 联系链接仍正常导航 | 阻塞链接等待事件回调 |
| JS 不可用 | 原生链接、可见地址与核心导航可用 | 让联系入口变成无响应按钮 |
| 复制失败 | 明确提示手动复制 | 记录复制成功事件 |
| 一个渠道临时停用 | 更新全局配置，突出另一渠道 | 在多个页面保留旧号码 |
| 工厂联系人换岗 | 工厂确认新接待人；全站构建与收发回归 | 只修改 Contact 页 |

## 09 Sanity 内容模型与字段规范

### 9.1 模型设计原则

CMS-01：采用 `siteSettings`、`page`、`category`、`article` 四种主要文档类型。SEO、图片、FAQ、样品、MOQ 为嵌套对象，不扩展成独立业务系统。没有商品 SKU、线索表、客户附件或聊天记录模型。

CMS-02：内容编辑使用固定结构。首页、制造、工厂、联系、博客列表、隐私分别使用固定 `pageKey` 的单例页面，共 6 个 `page` 文档；两个品类为 `category`，两篇首发文章为 `article`。固定页不能由编辑随意改路径或新建重复副本。

字段状态分为“必填”“可选”“条件必填”。必填错误阻止发布并在构建二次校验；长度建议是提示，不机械阻断有价值的正常英文内容。所有公开字段按可公开内容管理，内部协议、未授权照片与客户文件不上传 Sanity。[S15]

### 9.2 siteSettings：全局配置

| 字段 | 类型 / 必填 | 校验及用途 |
|---|---|---|
| factoryName / brandName | string / 必填 | 工厂英文名称 / 展示品牌；确认一致关系 |
| logo | image / 必填 | 可公开 Logo，含尺寸和替代文本 |
| email | string / 必填 | 单一已验证接待邮箱；去首尾空格、拒绝控制字符 |
| whatsappDigits | string / 必填 | 国际格式仅数字；本项目先做格式校验，再做真实账号验证 |
| whatsappDisplay | string / 可选 | 适合阅读的国际格式；必须与 digits 对应 |
| contactPersonOrTeam | string / 必填 | 经工厂同意公开的部门或联系人 |
| businessHours / timezone | string / 必填 | 明确工作时间与时区；不知道时不能生成“在线”承诺 |
| publicAddress | text / 必填 | 工厂确认可公开的地址或地区说明 |
| defaultMoq | moqPolicy / 必填 | 统一条件或明确按品类评估；见 9.6 |
| featuredCategories | reference[] / 必填 | 首期恰好两个已发布品类，顺序可调整 |
| defaultOgImage | image / 必填 | 分享图兜底；不得包含未确认业务承诺 |
| socialLinks | object[] / 可选 | 仅已确认官方账号；默认不展示 |
| channelStatus | object / 必填 | emailEnabled、whatsappEnabled；默认均为 true |

正式域名、环境标识、分析模式及密钥放在部署配置，不由普通内容编辑者任意修改。WhatsApp 号码格式校验只能证明结构，不证明号码已注册或有人接待。

### 9.3 page：固定页面

| 字段 | 类型 / 必填 | 校验及用途 |
|---|---|---|
| pageKey | enum / 必填 | home、manufacturing、factory、contact、blogIndex、privacy；唯一 |
| title / intro | string / 必填或按模板 | 页面 H1 与简介；首页等模板使用 |
| heroImage | image / 按模板 | 首页必填；其他页面按内容安排 |
| templateContent | typed object / 必填 | 根据 pageKey 显示固定字段组，不任意组合未知模块 |
| faqItems | faq[] / 按模板 | 问题、答案，首页与制造页使用 |
| seo | seo object / 必填 | 标题、描述、分享图；规则见 9.7 |
| contentUpdatedAt | datetime / 必填 | 实质内容更新时间，不能用部署时间自动覆盖 |
| factConfirmedAt | date / 涉业务页必填 | 工厂确认日期；仅非敏感公开日期，不存内部聊天记录 |

`templateContent` 必须与第 5–7 章模块一一对应：例如制造页包含 `options`、`preparation`、`sampling`、`productionSteps`；工厂页包含 `overview`、`factoryGallery`、`capabilities`、`qualitySteps` 和可选 `certifications`。Contact 的实际联系方式引用全局配置，不重复存储。

| 字段 | 类型 / 必填 | 校验及用途 |
|---|---|---|
| name / slug | string / 必填 | 英文名称；slug 小写短横线且路由唯一 |
| categoryCode / referenceCode | string / 必填 | 稳定公开编码；例如 hoodies / WEB-HOODIES |
| title / intro / heroImage | 对应类型 / 必填 | 标题、品类简介、首图 |
| samples | sample[] / 必填 | 本期每类至少 3 组，编号全站唯一 |

| customizationNotes | text / 必填 | 可改项和实际服务边界 |
| moqMode / moqOverride | enum + object | inherit 或 override；覆盖时完整填写规则 |
| samplingNotes | text / 必填 | 该类打样条件，必要时链接制造页 |
| evidenceImages | image[] / 必填 | 至少 1 张相关生产 / 细节 / 检查证据，可来自样品细节 |
| faqItems | faq[] / 必填 | 至少 3 个真实问答，避免纯近义重复 |
| relatedArticles | reference[] / 可选 | 0–2 篇，不输出未发布引用 |
| seo / contentUpdatedAt / factConfirmedAt | 对应类型 / 必填 | SEO、内容更新时间和事实确认日期 |

### 9.5 article：文章

| 字段 | 类型 / 必填 | 校验及用途 |
|---|---|---|
| title / slug / excerpt | string / 必填 | 标题、唯一 slug、列表摘要 |
| referenceCode | string / 必填 | 公开来源代码，不等同于客户标识 |
| coverImage | image / 必填 | 原创或获授权封面；含 alt |
| body | Portable Text / 必填 | 支持限定块，禁止空正文和任意脚本 |

| publishedAt | datetime / 必填 | 首次公开日期；首期不接受未来时间自动定时发布 |
| contentUpdatedAt | datetime / 必填 | 实质更新日期，不早于首次发布 |
| relatedCategories | reference[] / 可选 | 0–2 个；与正文相关 |
| linkToManufacturing | boolean / 可选 | 用于提供真实相关的服务入口 |

不开发定时发布功能：未来时间会触发提示并阻止当前发布，运营在实际发布时间手动发布。若未来增加调度，需同时解决静态站触发构建，不靠时间字段自动生效。

### 9.6 共享业务与素材对象

**MOQ 对象：** `mode` 为 confirmedQuantity 或 projectBased；`quantity` 仅前者必填且大于零；`unit` 必填；`basis` 说明 per style / per color / per style per color / 其他明确方式；`sizeMixing`、`conditions`、`confirmedAt` 为必填。projectBased 不输出数量，只输出经确认的评估条件。

CMS-03：默认规则只在 `siteSettings.defaultMoq` 维护；品类可以继承或完整覆盖。首页和 Manufacturing 的统一摘要引用默认规则；品类局部规则引用覆盖值并标记适用范围。FAQ 和正文中确需重复数字时必须做发布前一致性人工检查，CMS 不承诺自动理解所有自然语言中的数字。

**样品对象：** 编号、名称、摘要、图片数组为必填；面料、克重、版型、工艺说明为可选。取消单个样品时同步移除页面卡片，不影响整个品类 URL。

**图片对象：** asset、alt、caption、crop / hotspot 按需设置；`publicUseApproved` 必须为 true 才允许发布。非装饰图片 alt 不得为空；纯装饰图片使用空 alt 且明确标记 decorative。授权文件、客户品牌合同和拍摄元数据原件留在工厂内部，公开素材需清理不必要的定位或个人信息。

**FAQ 对象：** question、answer 必填；答案为文本或受控富文本。不要塞入虚构的零元价格、承诺或无关关键词。

### 9.7 SEO 对象与编辑校验

| 字段 / 规则 | 要求 |
|---|---|
| seoTitle | 必填、全站唯一；模板组合标题与品牌后约 35–65 个英文字符为提示范围，不是搜索引擎硬限制 |
| seoDescription | 必填、准确概括该页；约 120–170 个英文字符为提示范围，不据此保证摘要展示 |
| ogImage | 可选；缺失时用全局分享图 |
| canonical | 由正式域名 + 规范路由生成，不开放普通编辑覆盖 |
| indexability | 固定页面由路由策略控制；修改属于开发 / SEO 评审，不提供容易误点的全站开关 |
| slug | 首次上线前可改；上线后修改走重定向流程；拒绝重复、空白、路径穿越和保留路由冲突 |
| 引用与日期 | 拒绝坏引用、未来发布日期、更新时间早于发布时间等错误 |

CMS-04：普通内容维护无需改代码；新增同模板文章或品类无需开发新页面。新增导航一级栏目、页面模板、字段或业务能力属于需求变更，不承诺编辑器任意自助创建所有功能。

## 10 内容审核、发布与下线

### 10.1 发布生命周期

PUB-01：首期使用 Sanity 原生草稿 / 发布状态，加人工事实审核，不新增多级审批系统。工厂通过约定的内部方式确认资料，运营记录审核完成，随后发布。

```text
整理资料 → 草稿编辑 → 工厂事实审核 → 英文 / SEO 检查
→ Sanity 发布 → 构建触发 → 内容与路由校验 → 构建成功
→ 正式站部署 → 运营验证页面与联系方式
```

Sanity 保存草稿、Sanity 发布、网站部署完成是三个不同状态。公开站仅查询 published 视图；不能因为编辑端能看到草稿，就把草稿输出到正式 HTML。Sanity 官方提供 published / drafts 等读取视图，应显式使用适合正式站的视图。[S14]

### 10.2 构建与失败处理

PUB-02：发布、修改、撤回、删除均触发受保护的重建机制。使用托管平台构建钩子或等价 CI 触发方式，不将钩子密钥暴露在浏览器中。并发构建采用平台串行或取消旧任务策略，避免较旧结果覆盖最新发布。

PUB-03：校验缺必需数据、重复路由、无效联系方式、坏引用和泄漏占位符时，阻止发布产物替换正式站。错误信息包含文档 ID 与字段路径，便于定位。构建失败保留上一版可用站点，运营能够从平台日志或通知知道失败。

PUB-04：静态生成在构建时读取内容；新内容只有部署完成才对访客可见。构建可使用 `useCdn: false` 获取最新已发布数据；不因为需要 CMS 编辑而把公开站整体改成 SSR。[S04][S05]

### 10.3 撤回、删除和引用清理

PUB-05：正常下线先清理首页、导航、相关文章等引用，然后撤回对象并重建。下线后应从列表、导航、内部链接和 sitemap 同步消失。没有对应替代页面时旧 URL 返回 404；有实质对应替代时配置一跳永久重定向。

核心固定页、首期两个品类和两篇文章属于初始发布清单。正常编辑流程禁止误删单例；正式减少内容数量需同时更新受版本管理的发布清单并记录理由，否则校验阻止“成功发布一个空站”。

紧急撤回未经授权或错误内容时，先由开发使用受控临时维护页或撤回产物停止公开，再补充引用清理；不能仅因自动构建失败保留违规内容而认为处理完成。CDN 缓存及公开图片地址也需核查，删除 CMS 引用不等于所有缓存立即消失。

### 10.4 预览与安全边界

PUB-06：首期提供本地预览或访问受控的测试部署，不开发高级可视化编辑。测试域名 / Studio 入口需要适当访问控制和权限；保护的是内容与后台操作，而非仅隐藏登录界面的 URL。默认不建设公开草稿预览地址。

公开内容可用于营销；任何私密客户附件、内部报价、内部协议不进入 CMS。Sanity 的普通素材地址不能当作客户文件保密方案，本项目因此明确不提供上传功能。[S15]

## 11 SEO 功能与内容策略

### 11.1 页面意图分工

以下是关键词研究的起点，不是已验证搜索量、难度或固定 Google 排名。开发不依赖付费 SEO 工具；运营应在目标市场核对搜索意图后调整英文表述，不改变已确认的轻量范围。

| 页面 | 候选主题 / 关键词 | 必须避免 |
|---|---|---|
| 首页 | custom clothing manufacturer China | 把所有品类和服务词堆进 H1 |
| Manufacturing | low MOQ clothing manufacturer、small batch clothing manufacturing | 为每个近义词单独做重复页 |
| 品类 A / B | 对应品类 + custom manufacturer | 只有图片、没有制造条件 |
| Our Factory | 工厂名称、真实生产能力 | 冒用客户品牌、借用其他工厂资质 |
| 询价资料文章 | what to send for a clothing quote | 与服务页逐字重复 |
| MOQ 解释文章 | MOQ per style per color | 用通用算例代替本厂真实政策 |

### 11.2 技术 SEO 需求

| 编号 | 要求 | 验收方式 |
|---|---|---|
| SEO-01 HTML 可读 | 标题、正文、图片说明、主要链接在构建 HTML 中 | 禁用 JS / 查看源代码仍能读取核心内容 |
| SEO-02 元数据 | 每页唯一 title、描述、一个 H1、正确英文 lang | 自动扫 10 页，无缺失 / 重复 title；H1 数符合本项目规范 |
| SEO-03 规范 URL | 主域、HTTPS、尾斜杠统一；每个内容页生成自引用 canonical | 不含查询参数 / hash；不指向测试域名或错误页面 |
| SEO-04 sitemap | 自动列出正式、可索引、200 的规范内容页 | 首期默认 9 条；无 Privacy、404、草稿及重定向来源 |
| SEO-05 robots 与环境 | 正式核心内容可抓取；Privacy noindex；非生产不被公开索引 | 正式不得误设全站 noindex；受控预览有访问保护 |
| SEO-06 内链 | 导航、面包屑、文章与品类关联都是可用真实链接 | 抓取无孤立核心页、坏引用或不存在 Clothing 父页 |
| SEO-07 路由生命周期 | 改 slug 一跳永久重定向；无替代删除返回 404 | 检查响应码、循环和重定向链 |
| SEO-08 结构化数据 | 按 11.3 输出真实的组织、面包屑和文章数据 | JSON-LD 解析通过；与页面可见内容一致 |
| SEO-09 图片与分享 | 描述性 alt、响应式图片、正确 OG 标题 / 描述 / 图 | 无图片拉伸、错误跨域 URL 或分享测试域名 |
| SEO-10 Search Console | 验证正式站资源并提交 sitemap；交接访问权限 | 保存验证、提交记录；不把等待收录当功能失败 |

canonical、sitemap 与站内链接指向同一规范 URL。Google 会综合信号判断规范页，不能把配置 canonical 当作搜索引擎必须采用的指令。[S08]

sitemap 的 `lastmod` 由真实内容更新时间生成；没有可靠时间时可以省略，不能每次部署都刷新全站时间。提交 sitemap 不构成收录或排名保证。[S09] `robots.txt` 的禁止抓取不等于禁止索引，真正需要搜索引擎读取 noindex 的页面不能同时阻止抓取。[S10]

### 11.3 结构化数据映射

| 页面 | 类型 | 数据与限制 |
|---|---|---|
| 首页 / 工厂页 | Organization | 使用同一稳定组织 ID、名称、正式 URL、Logo、已公开地址 / 联系方式；无资质则不填 |
| 可索引内页 | BreadcrumbList | 与实际面包屑一致，按顺序提供真实层级 |
| 文章 | Article 或 BlogPosting | 标题、封面、真实作者或工厂组织、发布 / 更新时间、规范页面 |
| 品类 / 制造服务 | 可保留普通页面语义 | 不生成虚假价格、库存、评价或零元 Product Offer |

本期不把 FAQ 富结果、商品富结果或任何特殊展示作为交付承诺；FAQ 首先服务真实采购问题。标记需符合对应官方类型及页面可见内容要求，不为通过测试填入不存在的事实。[S11]

### 11.4 内容上线与迭代规则

CONT-01：先完成商业页和两篇文章，再持续根据工厂问答写内容。每篇有明确采购问题、原创资料输入、事实审核人和关联商业页。AI 可辅助提纲和英文整理，不能生成虚构订单、测试数据或工厂履历。

CONT-02：后续页面扩展不靠机械数量目标。定期检查搜索意图和工厂反馈；有相关访问但联系少时优先改现有信息与入口，而不是直接多发文章。低 MOQ 主题有独立资料和明显需求后再拆页。

CONT-03：不购买垃圾外链、不批量复制竞品、不建换国家名的重复页、不发布自导自演客户评价。外部曝光可来自真实合作、授权案例和行业资料贡献；站外推广不是开发前置依赖。

## 12 数据分析与工厂反馈

### 12.1 上线模式

DATA-01：部署配置支持 `analyticsMode=off` 和 `analyticsMode=approved`。默认 off：不加载第三方访客分析脚本、不发送联系事件；Search Console 配置仍可交付。统计代码已实现但未启用时，报告必须写“未采集”，不能写点击数为零。

approved：仅在明确使用工具、处理配置、适用同意要求和隐私说明后启用。若需要同意，拒绝或撤回后停止非必要采集；任何模式都不能阻止客户访问或联系。首期不强制购买分析服务或搭建自有分析后台。

### 12.2 事件字典

| 事件 | 触发点 | 业务含义 |
|---|---|---|
| page_view | 已批准分析模式下的真实页面访问 | 页面被浏览；不代表客户已阅读全部内容 |
| contact_whatsapp_click | 用户激活 WhatsApp 链接 | 尝试发起联系，不代表消息已发出 |
| contact_email_click | 用户激活邮件链接 | 尝试打开邮件程序，不代表已发送 |
| contact_email_copy | Clipboard 写入邮箱成功 | 成功复制地址，不代表实际询盘 |

DATA-02：联系事件只允许 `page_type`、`page_key`、`category_code`、`button_position`、`contact_channel`。没有品类时省略；position 为 hero、sample_card、inline、footer、mobile_bar、contact_page 中的受控值。首期不上传样品 ID 以减少维度数量，工厂仍可在预填消息中识别样品。

禁止参数包括完整 `href`、号码、邮箱、消息正文、客户资料、原始查询参数、文件名、剪贴板内容和错误堆栈。使用 Analytics 时需遵守其个人信息限制。[S12]

DATA-03：同一用户操作仅注册一条事件；只有 click 监听，不同时监听 touchstart + click 造成重复。内部事件错误捕获后结束，不 `preventDefault` 等待上报，不延迟原生导航；退出页面造成少量事件未送达属于已知限制，不据此虚构联系数。

### 12.3 GA4 或同类工具的最小化配置

DATA-04：如采用 GA4，先关闭本期不用的增强型衡量，尤其是自动出站点击采集，改用上方自定义事件。官方增强型出站事件可能包含 `link_url`，不能把带联系方式和消息正文的链接原样上报。[S13]

自动 page_view 也需检查：只传正式 origin + pathname，不传 query / hash；页面来源只保留经批准的来源域或类别，不直接传可能带个人信息的完整 referrer。所有事件不得自动追加未清理的 page_location。启用前使用网络面板和调试工具检查真实 payload，不仅检查业务代码中是否有显式邮箱字段。

首期不做访客指纹、全程会话录像、跨渠道身份拼接和用户级 Google 关键词归因。点击数据受同意、设备、拦截和离站影响，不能当作工厂实际收单记录。

### 12.4 最小业务反馈表

工厂使用现有台账即可，无需在网站新开发后台。推荐每周回传去标识汇总，每月结合搜索情况复盘；这是协作建议，不是本文已创建的自动任务。

| 字段 | 填写要求 |
|---|---|
| 收到日期 / 渠道 | 日期、Email 或 WhatsApp |
| 是否来自本站 | 确认 / 可能 / 未知；说明邮件别名、referenceCode 或客户自述依据 |
| 项目匿名编号 | 工厂内部去重使用，不提供客户姓名与设计稿 |
| 品类 / 大致数量 | 判断流量与工厂供给是否匹配 |
| 是否合格 | 可承接 / 待补资料 / 不匹配，并记录原因 |
| 进度 | 初次沟通、已报价、打样、订单等工厂已有状态 |
| 未继续原因 | MOQ、价格、品类、交期、客户暂停、失联或其他 |

联系点击率可用于比较入口，但不能称为询盘转化率。来源可靠的实际询盘才计算合格率；订单 / 打样按首次询盘批次跟踪，避免把本月订单直接除以本月新增询盘。

## 13 非功能需求与质量基线

### 13.1 性能

NFR-01：以静态页面、压缩图片和少量脚本为基线。以下为本项目工程预算，不是框架自动保证或 Google 排名条件。

| 项目 | 首期目标 | 测试条件 |
|---|---|---|
| 自有脚本 | 每页首次加载压缩后建议不超过 60 KiB | 不包含 Studio；依赖代码同样计入 |
| 样式 | 首次样式压缩后建议不超过 50 KiB | 禁止无目的打包整套大型 UI 库 |
| 首屏主图 | 交付尺寸下建议不超过 250 KiB | 清晰度优先，超出需说明与优化 |
| 首屏请求体积 | 建议不超过 1.5 MiB | 移动端首次加载、分析关闭、无预缓存 |
| 实验室测试 | 代表页 Lighthouse 移动性能建议 ≥90；LCP ≤2.5s、CLS ≤0.1 | 同一环境 3 次取中位数，记录工具版本、节流和报告 |
| 实际用户指标 | 有足够现场数据后评估 p75：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 | 新站没有现场数据不算测试失败 |

官方 Core Web Vitals 的“良好”阈值采用第 75 百分位。实验室测试不能代替现场 INP；无法保证所有国家、设备与网络都达到相同速度。[S17]

首屏图片不懒加载，非首屏图片按需加载；显式宽高避免布局跳动；不默认加载重型视频、字体或聊天 SDK。图片在浏览器加载前进行尺寸与格式优化，不把原始大图仅用 CSS 缩小。

### 13.2 可用性、可访问性与兼容性

NFR-02：以 WCAG 2.2 AA 相关设计规则为目标，包括键盘可达、可见焦点、正常文本至少 4.5:1 对比度、大字至少 3:1、内容重排、替代文本和状态反馈。实际交付不宣称未经审计的完整认证。[S16]

NFR-03：浏览器覆盖验收时的 Chrome、Edge、Firefox、Safari 主流稳定版；至少一台 iOS Safari 和一台 Android Chrome 真机。执行时记录实际版本，不在本 PRD 虚构测试已完成。视口覆盖 360、390、768、1024、1440px，并检查 320px 重排与 200% 缩放。

NFR-04：统计被屏蔽、字体加载失败、图片异常或 JS 禁用时，主要内容与联系入口仍可用。样品图片加载失败保留说明和布局；不承诺离线状态能访问未缓存内容或外部 WhatsApp。

### 13.3 安全与数据边界

SEC-01：后台账户使用独立授权和可用的多因素认证；最小权限分配；离职 / 更换协作方及时撤权。不能因 Studio 菜单隐藏就认为 API 数据安全，dataset 读权限与浏览器可见内容需单独核查。

SEC-02：建议生产内容 dataset 限制未认证读取，构建使用最小只读凭证；草稿不输出到前端。即便限制 dataset，上传的公开素材也按公开资产处理。公开已发布文案不是机密，但未发布商业资料不应依赖“知道地址才看得到”保密。[S14][S15]

SEC-03：密钥仅在本地安全环境或 CI secrets，禁止进入 Git、HTML、JS、日志与公开 sourcemap。构建取回原始对象后仅序列化页面需要的字段，不能把全部 CMS 响应嵌进页面。

SEC-04：富文本链接白名单允许本站相对路径及必要 HTTPS 外链，拒绝 `javascript:` 等危险协议；联系方式由受控函数生成。内容渲染使用安全转义，JSON-LD 输出经过安全序列化，不拼接未经转义字符串。

SEC-05：配置 HTTPS、合理的安全响应头与来源策略，启用内容安全策略时明确图片、样式和可选分析来源；先测试再收紧，不能为了“安全分数”破坏资源或联系链接。首期不接收文件、不设计客户秘密资料存储。

### 13.4 稳定性与恢复

OPS-01：CMS 故障时已发布静态站仍可访问；构建失败不替换正式站；内容与代码分别备份。建议内容每周及重要改动前导出，保留至少最近 4 次可恢复备份；正式上线前做一次恢复演练。这是项目维护约定，不是服务商 SLA。

OPS-02：保存代码 commit、内容备份 / 修订、部署 ID 和变更摘要。回滚部署不等于回滚 CMS：回滚后先校正错误内容或配置，再恢复自动构建，防止下一次构建重新发布故障版本。

## 14 技术实现与部署边界

### 14.1 架构基线

```text
工厂：提供品牌、能力、图片与接待账号
                     ↓
运营：Sanity Studio 编辑并发布公开内容
                     ↓
受保护的部署触发 / CI → 校验 → Astro 静态生成 → 静态托管
                                                   ↓
海外访客 → HTML / 图片 / 少量交互 → mailto 或 wa.me
                                                   ↓
                                     工厂邮箱 / WhatsApp 接待

并行数据：Search Console；经批准才启用的最小点击统计。
无：询盘 API、客户数据库、附件存储、聊天 API、订单系统。
```

TECH-01：Astro 使用静态输出，TypeScript 管理类型；Sanity 用于公开内容。框架、Node、集成包选择开发时互相兼容的稳定版本并锁定 lockfile，不在每次构建自动升级。[S04]

TECH-02：默认部署建议为 Cloudflare Workers Static Assets，发布 Astro 静态产物；不需要为此建设业务后端。也可换等价静态托管，只要支持自定义域名、HTTPS、真实 404、重定向、受保护部署触发和回滚。具体套餐、商用许可和额度在开通时确认，本文不锁定价格。[S18]

### 14.2 代码组织建议

```text
web/
  src/pages/          固定路由、品类与文章动态生成路由
  src/layouts/        全站与文章布局
  src/components/     导航、CTA、样品、FAQ、SEO、图片
  src/lib/            Sanity 查询、联系链接、分析适配器、路由
  src/types/          内容与联系上下文类型
  scripts/            内容校验、链接扫描、发布检查
  public/             静态资源、按部署需求输出的配置
studio/
  schemaTypes/        siteSettings、page、category、article
  objects/            SEO、图片、样品、FAQ、MOQ
ops/
  redirects.json      受版本管理的旧路径到新路径映射
  release-manifest   首期必须存在的页面与配置检查
  runbook.md          发布、回滚、联系方式变更与权限交接
```

这是建议目录，不要求复杂 monorepo、共享包平台或特定前端组件库。样式可采用熟悉的工具，避免仅为组件按钮引入大体积客户端框架。Studio 可独立部署，不并入公开站 JS 包。

### 14.3 环境配置

| 配置 | 保存位置 | 要求 |
|---|---|---|
| SITE_URL | CI / 构建配置 | 正式 HTTPS 主域；缺失或 example 域名阻止正式构建 |
| DEPLOY_ENV | CI | local、preview、production 明确区分 |
| SANITY_PROJECT_ID / DATASET | 构建配置 | 项目与数据集正确；不把标识误当私密权限保护 |
| SANITY_READ_TOKEN | 构建 secret | 私有读取所需，只读最小权限，不进入浏览器 |
| SANITY_API_VERSION | 构建配置 | 固定为经测试的 API 日期，不自动设为当天 |
| ANALYTICS_MODE / ID | 构建配置 | 默认 off；启用条件见第 12 章；ID 不是发信凭证 |
| BUILD_HOOK_SECRET | 平台 secret | 仅用于内容重建；可轮换，不写入公开 CMS 字段 |

构建脚本至少执行：类型检查、内容模式校验、必需路由检查、静态构建、内链检查、sitemap / canonical 检查、敏感信息与占位符扫描。测试数据允许在 local 使用，禁止进入生产产物。

### 14.4 部署触发与接口范围

本期唯一可能需要的服务端轻量连接是“CMS 内容事件 → 触发构建”，不接收访客询盘。如果平台直接提供受保护 Deploy Hook，可使用该方式；如需自行接收 Webhook，必须校验签名、拒绝无效请求、去除草稿事件噪声并限制重复触发。Sanity 官方建议对 Webhook 进行安全验证和可靠性处理。[S19]

不在 PRD 中定义 `/api/inquiries`、上传签名接口或发送邮件接口。所有后续启用表单 / 上传的需求都需要单独定义数据安全、可靠性和成本，不能偷偷归入“联系页开发”。

### 14.5 发布与回滚手册最低要求

OPS-03：手册应说明本地启动、构建、环境变量、CMS 修改与发布、检查部署、查询错误、替换联系方式、增加文章、添加品类、改 URL、撤回内容、回滚代码与内容、账号恢复和费用提醒。

首期至少演练四个操作：新增并发布一篇测试文章后撤回；修改邮箱并验证全站更新；模拟构建失败且正式站不被覆盖；回滚一次错误文案发布。测试文章与测试联系方式在正式验收前清理。

### 15.2 单页内容交付标准

CONTENT-02：每个页面的内容交付记录至少有 page ID、中文说明、英文终稿、素材清单、SEO 标题 / 描述、相关链接、联系上下文、审核日期和状态。状态可以用现有表格或文档管理，不开发新系统。

页面验收不是“已填满所有框”：内容必须真实、易懂、与该品类有关；可以隐藏没有材料的可选资质 / 案例，但不能隐藏核心 MOQ、打样和联系方式。MOQ 暂不能公开具体数量时，采用工厂确认的条件说明，而不是空白或假数字。

### 15.3 占位符与生产检查

CONTENT-03：开发数据统一使用明显占位符，例如 `[FACTORY_NAME]`、`[CONFIRMED_MOQ]`、`[CONTACT_EMAIL]`；这些仅用于文档或本地样例，生产构建须扫描并阻断。测试域 `example.com`、Lorem ipsum、Coming soon、未确认数字与演示手机号不得进入正式页面。

人工检查还需发现自动扫描无法判断的内容：错误工厂名、错误公司历史、未授权客户标识、模板残留、样品与工艺不符、将“可能支持”改写成“保证支持”。

| T-36 | SEO-04–05 | sitemap 默认 9 条、全部 200 且可索引；Privacy 与 404 不在其中，正式未全站 noindex |
| T-37 | SEO-06–07 | 内链扫描无死链；改 slug 后旧地址一跳永久重定向，无循环和不相关首页跳转 |
| T-38 | SEO-08–09 | JSON-LD 解析与实际内容一致；分享元数据及图片正确，无虚构评分价格 |
| T-39 | DATA-01 | analyticsMode=off 时不加载分析、不发事件；Search Console 交接独立完成 |
| T-40 | DATA-02–04 | approved 测试模式点击每个位置；事件一次、白名单参数、无原始 href / 联系资料 |
| T-41 | DATA-04 | 用带测试敏感查询参数的 URL 访问；网络 payload 的 location / referrer 已清理 |
| T-42 | DATA-01–03 | 拒绝或撤回分析许可 / 拦截服务；停止相应采集，联系入口不受影响 |
| T-43 | NFR-01 | 首页、制造页、两个品类与一篇文章执行性能测试并记录中位数；预算超标有修复或书面例外 |
| T-44 | NFR-02–04 / UI-01–09 | 真机、指定宽度、320px 重排和缩放测试；无按钮遮挡、焦点不可见和整页横向溢出 |
| T-45 | SEO-10 / OPS-03 | 正式资源验证、sitemap 提交、域名权限与发布手册交接完成；不要求即时获得排名 |

### 16.6 上线阻断清单

任一项存在即不得按正常版本上线：错误邮箱 / 号码或无人接待；核心页面缺失；工厂身份和关键能力不实；未经授权素材；样例业务数据残留；链接靠 JS 才能生成且降级不可用；隐私数据意外上报；草稿或密钥泄漏；正式全站 noindex；canonical 指错域；未知路径全部返回首页；无法发现构建失败；没有账号恢复和回滚方法。

两种可接受的分析状态是“关闭且无采集”或“按批准配置启用且验证通过”。不得以关闭分析为由取消代码降级测试；也不得为了交付埋点擅自启用未确认的数据处理。

### 18.2 主要风险与处理

| 风险 | 影响 | 处理原则 |
|---|---|---|
| 工厂素材不足 | 网站有结构但缺可信信息 | 优先补核心品类和工厂图，不填虚构证据 |

| 新增表单被误认为小改动 | 引入客户数据、通知和存储责任 | 另立需求与验收，不复用纯链接“成功”逻辑 |

### 18.4 上线后的建议复盘

建议以首个运营周期建立基线：先看目标页面能否被发现、查询是否相关，再看内容与联系入口，再结合工厂收到的实际项目。无展示先排查抓取和主题；有相关访问但联系少先检查资料与信任；实际询盘多但不匹配则修正对外条件；打样后不量产由工厂复盘产品、成本与履约。
