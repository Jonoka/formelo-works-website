# 服装工厂 B2B 独立站
## UI / UX 设计规范与开工文档计划 v1.0

**时尚编辑感 × 真实工厂 × 轻量询盘**

版本日期：2026-09-08  
配套基线：`b2b-apparel-factory-prd-v1.0.md`  
状态：视觉与开工准备建议稿，待网站负责人确认；不是已经完成的高保真设计或测试报告。

本文件补足原 PRD 对视觉方向、设计交付、素材准备和开发前置条件的描述。原 PRD 的业务边界不变：工厂自己的英文官网，网站团队负责搭建和 SEO，工厂通过邮箱与 WhatsApp 接待；首期 10 个内容 URL，不增加表单、CRM、上传、报价或订单系统。

**建议的第一项设计交付：用接近真实的文案和获准使用的素材，完成首页与一个品类页的桌面、手机四张高保真设计稿，再扩展其余模板。**

## 01 这次补什么，不补什么

### 1.1 原 PRD 的缺口

原 PRD 第 04 章给出了响应式、导航、联系按钮和真实图片原则，但没有明确的色彩、字体、摄影、版式、组件状态、动效和视觉批准流程。第 17 章也没有把视觉定稿作为页面开发前的独立检查点。仅凭这些描述，开发人员仍可能交付一个功能合格、却缺少服装品牌气质的通用工厂模板。

本次增加 UI 方向和实施规格，不重写业务。文档中的尺寸、颜色、动效和拍摄数量均为项目设计建议，不是行业标准或竞品原样参数。

### 1.2 视觉定位

建议采用 **Fashion Editorial + Modern Manufacturing**：以服装品牌画册式的摄影和排版形成第一印象，以清楚的制造条件和真实生产证据支持采购决定。

| 必须同时做到 | 对应表现 |
|---|---|
| 像懂服装的生产方 | 成衣、版型、材质和细节为视觉主角，不让厂房外观占据全部首屏 |
| 仍然是 B2B 工厂官网 | 首屏明确制造服务、中国工厂、品牌客户，不使用购物车或促销语言 |
| 联系起来容易 | Email 与 WhatsApp 显眼、可识别，不藏在创意导航中 |
| 便于持续运营 | 固定模板和统一视觉变量，内容更新不需要重新设计整页 |

### 1.3 文档优先级

已确认的业务边界优先；经批准的变更记录优先于旧版对应描述。本文在视觉批准前属于建议，不自动把用户未确认的审美选择变成硬性要求。批准后，更新 PRD 版本或在其首页标明本补充文件的版本与适用章节；不要让开发同时面对两套未说明优先级的数值。

本次不交付已批准的 Figma 原稿、真实工厂素材包、完整英文终稿或生产代码；这些交付的范围、负责人和完成条件在后文定义。

## 02 同类网站参考：分别借鉴，不整站照搬

研究日期为 2026-09-08。已查阅官网公开内容与可访问图片，并查看第三方保存的 Hawthorn 页面截图。未完成三家现站的浏览器全页截图核验，因此不把其当前字体、间距、动效或手机表现当作已测量结果；下面明确区分视觉素材观察与内容结构观察。它们不是本次核验的 Google 固定排名，也没有公开转化率作为设计收益依据。

### 2.1 Hawthorn：视觉主参考之一

其官网展示服装模特主图，并围绕初创品牌、服装品类、定制能力和制造步骤组织内容；可访问的官方主图采用干净浅色背景与服装展示。[R01] 第三方保存的旧页面截图可见黑色导航、人物大图和简短行动入口，但它不能代表现站最新布局。[R04]

**建议借鉴：** 让衣服和版型先建立审美印象，再展开制造信息；采用简短标题与明显入口。**不照搬：** 英国业务叙述、其 MOQ 和服务承诺、素材，以及旧版页面的具体排版。

### 2.2 Create Fashion Brand：品牌与制造结合的参考

CFB 官网把从零开发、基础款定制和空白服装采购区分呈现；其公开图片既有服装造型，也有生产现场。[R02] 这说明制造服务内容可以与时尚摄影并存，而不必全部采用工业设备照片。

**建议借鉴：** 成衣表现、材质特写和工艺证据的组合；把不同制造方式讲清楚。**不照搬：** 商城、购物车、庞大目录及其品牌定位、产地和经营数字。你们首期仍然只做直接联系。

### 2.3 White Cotton：采购信息结构参考

其官网提供品类、制造服务、面料、工艺、合作步骤及资源入口。[R03] 本项目借鉴的是信息分工，不是将它当作已核验的当前 UI 像素样本。

**建议借鉴：** 让买家从“能做什么”自然走到“如何开始”。**不照搬：** 首期即铺开大量工具、专题和栏目。

### 2.4 参考结论

视觉方向以 Hawthorn 和 CFB 的服装展示思路为主，采购信息组织借鉴同类站的清晰分工。竞品图片只用于研究和内部参考，不进入工厂正式素材库；最终页面使用工厂实物、真实生产图和合法授权素材。不能通过抄袭素材来完成所谓风格对齐。

## 03 推荐风格：克制、当代、有服装质感

### 3.1 选定一个默认方向

建议默认采用“暖白底 + 炭黑文字 + 大幅服装摄影 + 少量深橄榄色点缀”。它适合作为尚未确定全部品类时的中性起点。首发品类确定后，在摄影、局部字号和图片节奏上调整，不为每个品类另建一套主题。

| 维度 | 建议做法 | 不采用的做法 |
|---|---|---|
| 画面 | 大图、统一色温、清晰版型与面料细节 | 每张图不同背景、过度修色、低清拼图 |
| 排版 | 大小标题有明显层级、非对称图文、留白 | 每个模块都塞进同样的圆角卡片 |
| 气质 | 当代服装工作室 + 专业制造 | 通用蓝色企业模板、黑金“奢华”、荧光科技风 |
| 工厂感 | 工序、手部操作、检查记录与短说明 | 首屏铺满机器、旗帜、奖章和口号 |
| 交互 | 快速、直接、少量反馈 | 开场动画、滚动劫持、鼠标追随、自动视频 |
| 采购信息 | 数字、单位、条件一起出现 | 为了“高级”缩小或隐藏 MOQ 与联系入口 |

### 3.2 对品类的适配

若优势为街头休闲：增加廓形、厚实面料、印绣花细节的视觉分量，标题稍有力度。若优势为女装或轻正装：通过垂感、剪裁与更细腻的摄影调整气质。若优势为运动服：突出结构、缝线和面料表现，但不随意加入未验证功能宣称。

不在确定品类前武断选定“奢侈女装风”或“潮牌涂鸦风”。风格应服务工厂能生产的衣服，而不是让素材去勉强适配一个漂亮但不相关的模板。

### 3.3 视觉方向批准标准

用真实或接近真实的内容评审首屏，而不是只看空白组件。让评审者回答：这是服装制造商还是零售品牌？服务谁？能做哪些主要品类？在哪里生产？如何联系？再检查审美是否符合工厂希望接到的客户类型。

以上是小范围设计评审问题，不是经统计验证的转化率实验。风格可以有主观偏好，但采购信息清楚、联系可见和照片真实必须同时通过。

## 04 视觉变量：颜色、字体和层级

### 4.1 建议配色

| 变量 | 色值 | 使用范围 |
|---|---|---|
| background | `#F5F3EF` | 页面暖白主底色 |
| surface | `#FFFFFF` | 参数、内容和必要浮层的白色底 |
| text-primary | `#161616` | 标题、正文、主按钮背景 |
| text-secondary | `#625F59` | 摘要、图注、辅助说明 |
| accent | `#56634D` | 少量强调、正文链接或局部色块 |
| accent-hover | `#46533E` | 强调按钮的悬停状态 |
| divider | `#DAD6CF` | 装饰性分隔线，不作为控件唯一边界 |
| control-border | `#7A766E` | 描边按钮等需要辨认的控件边界 |

基础搭配按 sRGB 对比度公式计算：主文字 / 暖白约 16.33:1；辅助文字 / 暖白约 5.74:1；白字 / accent 约 6.39:1。该计算只验证纯色组合，不能替代图片叠字、透明度及所有交互状态测试。装饰线 / 暖白约 1.31:1，不可当作必要交互边界。正常正文最低 4.5:1、大字最低 3:1 的依据见 W3C。[R05]

### 4.2 建议字体与字号

英文首期建议 **Manrope 一套字体**，使用 400 / 500 / 600 层级；未加载时回退系统无衬线字体。它是候选而不是工厂既有品牌规范；有正式品牌字体时先核对授权、Web 使用与加载成本。候选来源见 Google Fonts。[R09]

| 用途 | 桌面建议 | 手机建议 |
|---|---|---|
| 首页主标题 | 56–72px，行高约 1.05–1.12 | 34–40px，按内容自然换行 |
| 内页 H1 | 44–56px | 30–36px |
| H2 | 32–40px | 26–30px |
| 正文 | 16–18px，行高 1.6–1.75 | 至少 16px |
| 辅助文字 | 14px，保持可读对比 | 14px，不承载关键采购条件 |

不靠全大写、极细字或极低对比表现高级感。MOQ、交期和联系说明使用正常正文层级。字体文件不作为本次附件提供；实施时从合法来源取得并保留许可记录。

## 05 布局、图片比例与响应式规则

### 5.1 页面骨架

保留原 PRD 断点：手机小于 768px，平板 768–1023px，桌面从 1024px 开始；小于 1024px 折叠菜单。设计主画板采用 1440px 与 390px，并验证 320、360、768、1024px 和缩放场景。

| 项目 | 建议基线 |
|---|---|
| 桌面内容 | 最大 1200px；宽屏摄影可以铺满，但文字回到同一网格 |
| 网格 | 桌面 12 栏，平板 8 栏，手机 4 栏 |
| 页面边距 | 桌面至少 40px；平板 32px；手机 20px，极窄屏可降至 16px |
| 网格间隙 | 桌面 24px；手机 16px |
| 模块间距 | 桌面 80–112px；手机 48–64px |
| 文章阅读 | 不超过 760px，实际文本建议约 60–75 个英文字符宽度 |
| 圆角与阴影 | 按钮 4px；图片 0–4px；默认无重阴影 |

尺寸是统一起点，不能为了精确数字把真实英文标题截断。允许流体字号和自然增高，不将组件高度锁死。

### 5.2 首屏与图片

首页桌面默认采用左文右图：文字约 5 栏，摄影约 7 栏。主图优先真实成衣造型或有质感的服装静物；文字在实色底上，减少换图后对比度失控。首屏高度由文案和图决定，不强制 100vh。

手机改为标题、说明、双 CTA、图片的顺序，联系动作不被长图推到很深的位置。390×844 主画板中应能在首屏找到主要联系动作；320px 与放大文字时优先保留内容，不为“首屏全部显示”而缩小字体。

服装品类图建议统一 3:4 或 4:5；样品卡同一列表只选一种比例。工艺图可用 4:3，文章封面用 16:9。图片框比例、可裁切区域和完整展示要求分别定义；工艺证据不能为了整齐裁掉关键缝线或标签。

### 5.3 内容为空时

没有获授权证书则隐藏证书区；只有两篇文章就显示两篇；照片失败仍保留说明和联系链接。主图与核心样品缺失不以随机图库替代，按原 PRD 的内容验收规则处理。

## 06 首页与品类页的视觉落地

### 6.1 首页：不增加模块数量，改变表达方式

| 原模块 | 视觉处理 | 必须保留的信息 |
|---|---|---|
| HOM-01 首屏 | 实色文本区 + 大幅服装图，大标题、双联系按钮 | 中国工厂、品牌定制服务、目标客户 |
| HOM-02 两个品类 | 两张较大的画册式品类图，不做密集商品网格 | 品类名称、制造能力摘要、真实页面入口 |
| HOM-03 能力证据 | 2–4 条短说明配细分隔线，必要时配局部细节 | 能力的真实依据与适用条件 |
| HOM-04 制造摘要 | 少量步骤、MOQ / 打样摘要、制造页入口 | 数量单位和条件不能变成难读脚注 |
| HOM-05 工厂与流程 | 纪实生产图 + 短文，形成与造型图的切换 | 真实工厂身份和生产能力 |
| HOM-06 FAQ 与 CTA | 简洁问答、明显结束区，深底或暖白均用统一变量 | 有用答案、Email 与 WhatsApp |

首屏英文方向可以继续使用 “Custom Clothing Manufacturing for Emerging Brands”，配一行简短的中国工厂说明。文案应在布局评审时一起调整，而不是在完整中文设计稿完成后才机械塞入英文。

主按钮建议黑底浅色字 “Chat on WhatsApp”；次按钮描边 “Email Our Factory”。两者视觉有主次，但都直接进入渠道，不增加中转表单。导航仍用清楚的 Clothing、Manufacturing、Our Factory、Blog、Contact Us。

### 6.2 品类页：画册展示 + 采购规格

页首先显示品类制造定位、样品主图、能力摘要和双 CTA。样品区采用整齐图幅与简短说明，不显示价格、折扣、库存或购物车。

桌面样品建议 3 列，手机 1 列，以看清版型和细节；内容更紧凑的方案须经过真实手机评审。卡片保留公开编号、工艺摘要，以及两个小型但有足够触控区域的联系入口。卡片外层不能再包一个包含内部链接的整卡链接。

面料、克重、版型、MOQ 与打样使用易扫描的规格行，不把所有文字叠在图片上。页面后段加入相关工艺 / 质检图片，再接 FAQ 和联系。沿用原 PRD：每品类至少三组获授权样品；不新增筛选、灯箱或样品独立详情页。

## 07 其余模板如何保持同一风格

| 模板 | 视觉与内容安排 | 不做的事情 |
|---|---|---|
| Manufacturing | 简短引导、轻量锚点目录、编号步骤、MOQ 说明面板；照片支持对应工艺 | 每个工艺一张相同大卡片；把条件藏进默认不可发现的交互 |
| Our Factory | 纪实图片穿插文字，少量工序图注，质检说明清楚 | 无依据的数据大屏、客户 Logo 墙、模板地图 |
| BlogIndex | 像采购栏目而非资讯门户；统一封面、标题和摘要，两篇照样自然成版 | 为凑版式加入假文章、分类筛选和热榜 |
| Article | 阅读为主；清楚层级、目录、表格、图注与相关制造入口 | 两侧广告、文章中持续弹窗、正文极小浅灰字 |
| Contact | 留白但不空洞；邮箱、复制、WhatsApp 和工作时段立即可见 | 用巨大装饰图把联系方式挤到下方；表单 |
| Legal | 干净正文模板、清晰标题和生效日期、普通页脚 | 底部营销浮条、复杂视觉效果 |

### 7.1 设计交付数量

10 个内容 URL 复用 8 类模板。建议先做首页与一个品类页的桌面、手机四张关键稿；方向批准后补齐其余六类模板的桌面与手机。最终覆盖 16 个模板级主要视图，不为第二个品类或第二篇文章重复设计同结构画板。

404 使用通用排版并给出说明即可。768px 的规则可以用网格和局部示例交付，不强制为所有模板再画一套平板图。菜单展开、复制成功 / 失败、焦点、长标题等作为状态补充，不算新增业务页面。

### 7.2 设计工具与交接形式

可使用 Figma、Penpot 或可检查的 HTML 设计原型，选团队真正能维护的方式。不要求先购买指定工具，但必须能查看尺寸、素材、组件与状态；只交一张压平的长截图不足以作为完整开发交接。

图像生成的概念图可以参与方向讨论，但不等于可开发的响应式设计，不替代组件规格，也不作为真实工厂证据。正式页面所需文字必须是 HTML 文本，不能把整张网页概念图直接当站点实现。

## 08 摄影与素材准备：先决定怎么拍，再决定怎么排

### 8.1 素材任务清单

| 素材组 | 建议准备 | 必须说明 |
|---|---|---|
| 首页主视觉 | 1 组真实成衣造型或高质量静物；准备桌面与手机裁切 | 衣服是否本厂样品、可公开范围、裁切安全区 |
| 两个品类 | 每类至少 3 组样品；建议补正面与一个工艺细节 | sampleCode、面料、版型和对应工艺 |
| 工厂与质检 | 原 PRD 至少 3 张真实工厂图；建议覆盖生产与检查 | 实际工序、地点、可公开人物与标识 |
| 文章 | 询价资料与 MOQ 的真实辅助图，可复用已授权素材 | 不是虚构技术包、客户项目或生产记录 |
| 品牌 | Logo、标准拼写、可用颜色与字体资料 | 资产来源、使用权限和最小显示要求 |

一次拍摄可争取约 12–20 张可用原片，供不同裁切复用；这是拍摄规划，不是提高原 PRD 的硬性数量门槛。没有模特预算时，统一背景的平铺、挂拍、版型和细节摄影也可以作为主要方向。

### 8.2 拍摄与后期原则

服装熨整、背景清理、稳定照明，避免混乱色温和过度锐化。不同样品保持相近机位和比例。先拍干净实物，再补细节与工序。保留原片，不只提供被聊天软件压缩的小图。

可以做正常曝光、裁切和背景整理，但不能把面料颜色、厚薄或瑕疵修成不真实的能力证据。人物、客户 Logo、证书与样品项目分别确认可公开权限；内部报价、技术资料和客户设计不要作为装饰背景进入照片。

### 8.3 素材台账字段

`asset_id`、原文件名、用途、关联页面 / 样品、摄影者或来源、授权状态、桌面比例、手机比例、裁切焦点、alt、图注、最终文件版本、审核人、审核日期。

Sanity 原生图片支持 crop / hotspot，但前端图片处理必须正确使用这些字段才会体现裁切。[R10] 默认先用一张高质量图片和焦点；仅在手机确需不同构图时增加可选 `mobileImage`，不为每张图强制上传两份。

内部授权证明留在受控文件中，公开 CMS 只保存必要公开素材及审核状态。竞品参考图和正式可用素材必须分开目录，禁止混用。

## 09 组件、交互状态与动效

### 9.1 公共组件规格

| 组件 | 基础样式 / 行为 | 必须交付的状态 |
|---|---|---|
| Header | 实色背景、细分隔线；不依赖复杂透明变色 | 默认、品类展开、手机展开、键盘焦点 |
| ContactActions | 一主一次；高度建议 48px，窄屏可换行 | 默认、hover、focus-visible、active、单渠道降级 |
| MobileContactBar | 双文字入口，保留底部安全区；高度随内容 | 默认、菜单打开时隐藏、长文案和缩放 |
| SampleCard | 统一图幅、编号与摘要、双渠道文字入口 | 常态、图片失败、长标题、无可选参数 |
| ArticleCard | 封面与文字整齐，链接不嵌套 | 常态、焦点、无额外关联内容 |
| FAQ | 使用可访问的展开控件，答案在 HTML 内 | 收起、展开、键盘操作 |
| CopyEmail | 普通按钮，反馈不改变周围布局 | 默认、复制成功、复制失败、无 JS |

沿用原 PRD 的小于 1024px 非模态折叠菜单，不悄悄改为全屏复杂模态。当前页联系入口仍直接使用真实 href，分析失败不拦截导航。按钮至少满足项目约定的 44×44 CSS px 触控区；这比 WCAG 2.2 AA 的目标尺寸最低规则更保守，不能把 44px 错说成该条 AA 的统一最低要求。[R06]

### 9.2 动效边界

hover、颜色、描边反馈建议 150–200ms；照片轻微缩放最多约 1.02，且不能裁掉关键内容。首期可以完全不做滚动进入动画，优先把静态版式与摄影做好。

如确有非必要动画，支持 `prefers-reduced-motion`，在减少动态效果模式下关闭位移和缩放。[R07] 核心内容默认可见，不允许脚本未运行时整页停留在 opacity: 0。不做滚动劫持、全站横向滚动、开屏等待、光标追随和自动有声媒体。

### 9.3 可读性优先级

采购条件、正文、联系入口的可读性高于装饰。图片上确需文字时使用经测试的遮罩或实色区域，并对桌面、手机实际裁切分别验证。不能仅靠“看起来差不多”判定对比度。

## 10 时尚 UI 与 SEO、性能如何一起落实

### 10.1 内容不能为了视觉被隐藏

标题、制造能力、MOQ、文章和导航继续由静态 HTML 输出。大标题有真实文本，小字标签不替代完整 H1；导航用客户能理解的名称，不改成无意义的数字或创意代号。Google 的 SEO 指导强调清楚内容和可理解结构；视觉包装不替代有用信息。[R08]

首页负责概览，品类和制造服务负责解释采购条件，文章负责回答知识问题。通过层级和留白改善阅读，而不是删光文字，或把采购信息全部折叠到深处。不能因风格升级新增大量近义关键词页面。

### 10.2 保留原 PRD 的性能预算

每页自有压缩脚本建议不超过 60 KiB，样式不超过 50 KiB；移动首屏主图建议不超过 250 KiB、首屏总体积不超过 1.5 MiB。全部沿用原 PRD 第 13 章，例外须记录理由与测试结果，不因为 UI 要时尚就自动增加重视频和聊天 SDK。

这些是工程预算，不是素材原片大小限制，也不是框架保证。以首屏成品清晰度、实际网络和页面指标综合判断。Astro 可用于图片优化，但需要正确处理本地 / 远程图片与尺寸；Sanity 图像处理链路也要按实际选择实现，不能假定任何 CMS 图片会自动得到最佳优化。[R11]

### 10.3 字体和媒体

只加载当前英文站所需的字体文件与字重；有合法 Web 许可才部署。采用可靠回退字体并检查字体切换后的换行与布局偏移。不上线全套字体包，也不把桌面高分辨率原图直接传给手机。

首屏关键图不懒加载，下面的摄影按需要延后；所有图片保留宽高或比例，避免加载后顶动正文。先完成静态画面，未来确有价值才评估视频。

### 10.4 验证口径

实际用户数据足够后评估 p75 的 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；新站没有现场数据，不等于测试失败。[R12] 上线前保留原 PRD 的实验室、真机、无 JS、缩放和键盘测试，不把一张设计稿或一个性能分数当成完整验收。

## 12 每组开工资料写到什么程度

### DOC-01 PRD 与范围基线

保持原文为唯一功能依据，明确 10 URL、8 模板、直接联系、不收客户资料。增加本次变更编号、UI 补充版本和批准状态。原需求编号保留，后续任务用这些编号关联，不重新把同一需求编号一遍。

设计稿使用实际或接近实际长度的英文；至少首页与一个品类页采用接近最终的真实素材。极少数待替换图片必须标明比例、构图约束、负责人和期限，不能随意用完全不同构图占位。

完成条件：开发不需要猜测手机布局、触发方式或图片来源；网站负责人批准视觉，工厂确认事实与素材权限。设计中出现超出 PRD 的交互，先提变更，不直接开发。

### DOC-04 内容、SEO 与素材总表

完成条件：10 页都有明确内容任务与负责人；首页、品类、制造和联系的关键文案能供设计使用；正式发布前全部核心信息审核通过。两篇文章可以与工程并行完成，不因它们尚未写完阻塞仓库初始化。

## 14 开工顺序与三道批准门槛

### G0：可以开始视觉设计

输入包括真实首发品类、品牌写法或获认可的临时字标、客户类型、首页和一个品类的接近真实文案，以及一组可以评估的服装图片。没有完整素材包也可以做风格草案，但必须清楚哪些元素会变；不能把空白灰框原型当作已验证的时尚方向。

动作：先做结构草图，再做最多两种小型风格样张。样张包含首屏、品类卡和联系按钮即可，不把两个方向分别扩展成全站。

### G1：可以开展正式页面开发

批准一套视觉方向；首页和一个品类的桌面 / 手机稿通过；公共组件、响应式、主要内容与图片处理规则明确。其余模板至少已完成结构与组件映射，并在对应页面开发前批准高保真。

允许此前并行做仓库、静态部署、CMS 草案和图片链路验证。未通过 G1 时，不建议大量编写最终页面样式，以免“边猜风格边堆页面”导致整体返工。

### G2：可以发布正式站

八类模板覆盖完成，10 页核心内容审核完毕；真实邮箱和 WhatsApp 收发测试通过；功能、视觉、性能、安全与 SEO 阻断项清零；域名、账号、素材授权、隐私与回滚方法完成交接。

| 顺序 | 主要输出 | 依赖 |
|---|---|---|
| A 资料与范围 | 首发品类、素材盘点、页面任务、负责人 | 工厂提供事实 |
| B 结构与方向 | 关键页草图 + 小型风格样张 | 接近真实内容 |
| C 关键设计批准 | 首页 / 品类四张稿 + 核心组件 | 选定一种方向 |
| D 设计扩展与技术验证 | 其余模板、CMS 映射、发布链路 | G1；可分批批准 |
| E 页面实现与联调 | 复用模板、填内容、联系入口、SEO | 各模板已批准 |
| F 验收与上线 | 功能 / 视觉结果、接待确认、发布记录 | G2 |

不要求所有长文章、运营手册和未来专题都在第一行代码前写完。但品类、主视觉、关键布局和联系行为不能一直悬而未决。
